# Stage 4b: one table only

Build ONLY data.target, using the confirmed requirements, selected DBMS and saved plan rules. Return a compact JSON object {"table":{...}}. Do not repeat the plan, other tables, documents, SQL or reasoning. The parent data contains only primary and unique keys, their column definitions and sample key values. Use those definitions and values exactly. Other tables are generated in separate requests.

Table contract:
{"table":{"name":"requested_table_name","purpose":"Purpose, at least 10 characters","columns":[{"name":"id","type":"integer","nullable":false,"description":"Meaning of this attribute"}],"primaryKey":["id"],"unique":[],"foreignKeys":[],"checks":[],"indexes":[],"functionalDependencies":["id -> all non-key attributes"],"normalization":"Concise dependency-based 1NF, 2NF and 3NF assessment, at least 20 characters","rows":[{"id":1},{"id":2},{"id":3}]}}

- Every listed array is required, including empty arrays. Return exactly the requested name. Preserve all attributes and relationships from requirements for this table. Maximum 50 columns. Use three meaningful synthetic rows unless confirmed requirements explicitly need more (maximum 30), with optional nulls and useful boundary cases where appropriate.
- All identifiers are lowercase ASCII letters, digits and underscores, starting with a letter, maximum 48 characters. Avoid reserved SQL names for columns used in checks. Prefix constraint/index names with the table name and avoid all reservedNames.
- Column types: integer, bigint, string, text, decimal, boolean, date, timestamp, uuid, json. For strings include length (default 255); decimals precision and scale (default 12,2). Omit inapplicable properties. Optional default is a literal scalar/null, never SQL. IDs are explicit safe integers or UUID strings, not auto-increment. Dates/timestamps are ISO strings, decimals numbers, booleans JSON booleans, json values serialized strings. No real personal data or plaintext passwords.
- Each table has a non-null primary key. Unique keys are arrays of column-name arrays. Many-to-many links need a composite primary or unique key. Provide meaningful functional dependencies and candidate-key analysis; a surrogate key alone does not prove 3NF.
- Foreign key shape: {"columns":["parent_id"],"refTable":"parents","refColumns":["id"],"onDelete":"RESTRICT"}. Allowed delete actions: RESTRICT, CASCADE, SET NULL, NO ACTION. Reference only data.parents or this table itself; referenced columns must be a declared primary/unique key. Copy exact parent types/lengths and use existing parent sample key values. SET NULL requires nullable columns. Do not cascade-delete retained financial/history evidence.
- Checks: {"name":"table_rule_check","expression":"amount >= 0"}. Use portable scalar comparisons, AND/OR/NOT, IN, IS NULL, arithmetic and optional COALESCE/ABS/LOWER/UPPER only. No subqueries, comments, semicolons, vendor functions or DDL. Enumerations need checks or reference tables. Avoid raw boolean checks; the compiler enforces the boolean domain.
- Indexes: {"name":"table_lookup_idx","columns":["status"],"unique":false}. Support actual query patterns; missing FK indexes are added by the compiler.
- Every row must satisfy non-null, type, length, unique, foreign key and check constraints. Include every required column and valid timestamps. Null is not an omitted default. Coordinate boundary values with the supplied parent rows and business rules. Self-reference seeds must reference a row returned in this table.
- Cross-row constraints and authorization belong to documented transaction/application policies unless an actual database constraint enforces them. Do not falsely claim row CHECKs enforce those rules. Keep descriptions and normalization concise and specific; do not return independent Markdown or SQL files.
